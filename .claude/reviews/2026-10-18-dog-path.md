## Confirmed
1. **Concurrent compaction can lose points** — `pep_core/lib/src/project_session.dart` compactPaths
   + `_decode`. (a) `_decode` caches by (collection/id, rev): two compactors publishing the same
   rev N+1 → the receiver keeps the later one but `_decode` returns its own cached content, so the
   post-sync check is wrong (repro: owner purged 3, bob purged 1, late joiner sees 1 point).
   (b) Even with a correct cache, a competing same-rev chunk may reach the broker after the sync
   probe and win. Fix: cache key rev+time+signer (or invalidate on ItemUpdated); design so that
   concurrent writers never overwrite each other (chunk id per compactor + union, or purge only in
   a later round if a chunk older than a grace period holds the point); optional safety net: the
   source republishes its points found in neither `path_pt` nor a chunk.
2. **Overlapping `publishPosition` corrupts the offline queue** — `_flushPath` is not
   single-flight: duplicates, lost points, `RangeError` from `removeAt(0)`. Fix: single-flight
   flush, remove by identity.
3. **Path publishing blocks the live position** — the path point is flushed before the position
   and only `TransportException` is caught: e.g. `path_pt` not declared (older project before the
   owner joins) → `publishPosition` throws every time, the live position is never shared, the
   queue grows. Fix: position first, then flush; handle non-transport errors separately.
4. **Password change can still lose points** — `compactPaths` returns 0 if a compaction is
   running; `minAge: zero` still skips points with a fix time after the owner's clock; points
   published during the change are cleared (or left undecryptable). Fix: await the running
   compaction, compact without time cutoff, plus the source-side republish.
5. **Offline queue only in memory** — dropped on close/kill; DESIGN.md overstates ("nothing is
   lost"). Fix: persist/restore API for the app, or document; also: draining a long queue delays
   the live position (fixed by 3); a broker rejection at the head blocks the queue.
