# Review of the docs-sync branch, 2026-10-27

Notes, docs and code checked against each other (three read-only audits, one per package), then
one `protocol-reviewer` round on the diff. No library behaviour changed.

What changed:
- DESIGN.md, packages/CLAUDE.md, the READMEs, TODO.md and doc comments now say what the code
  does: identity export AD `"pepid1."` (with the dot, format now in *Wire formats*); only the
  `extra` object of JSON documents is preserved (`Position` has none); `Run.sources` = JSON
  `src`; KDF lower bounds; restricted blocks on reassignment; tie rule wording; a failed
  `deleteChannel` leaves the session open; `close` clears the session's ephemeral items; ACL
  limits; one session per channel per `Mqtt5Transport`; mosquitto filters denied subscriptions
  silently; GPX elements dropped on rewrite; `ChannelDeleted`/`ProjectDeleted` can be
  vandalism.
- Versioning: the pre-release rule (formats stay v1, change in place) is written into
  packages/CLAUDE.md and the protocol-reviewer agent, which used to ask for version bumps.
- `IdentityBackup` renamed `IdentityExport` (user, 2026-10-27); wire format unchanged.
- e2e.sh: a step for every CLI command (`export`, `rm`, `run source`, `run rm` were missing);
  the `! cmd` refusal checks never failed under `set -e` — now `refused` (exit 1 expected) and
  `absent` (with a positive control for the broker's topic list); `--` before positional ids.
- fetch_sodium_js.sh: the no-argument default works (it expanded to one word).
- Unused `meta` dependency removed from pep_channel.

Still open:
- **TTL bounds are checked only when an access list is read** (`CollectionPolicy.fromJson`,
  10 s – 7 d), not when one is written: `updateProject(positionTtl: 5 s)` publishes an access
  list every later `join` rejects (`ChannelNotFoundException`), and `create` with such a TTL
  leaves meta + an invalid ACL behind. Fix: check the range in `ChannelAcl` (as serialized,
  `ttl.inSeconds`) so `create`/`updateAcl` throw before publishing; contract tests for both.
